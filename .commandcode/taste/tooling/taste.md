# Taste
- PowerShell scripts containing non-ASCII text (e.g., Chinese comments) that will be run under Windows PowerShell 5.1 must be saved as UTF-8 **with BOM** (e.g., `New-Object System.Text.UTF8Encoding $true` before `WriteAllText`): PS 5.1 reads BOM-less UTF-8 files as ANSI/GBK, and mangled comment bytes can corrupt the script structure, producing baffling runtime errors (here: GDI+ "参数无效" on every drawing call) even though the same code works fine interactively or in ASCII. Confidence: 0.9
- PowerShell passes an array variable used as a positional function argument by ENUMERATING it into multiple parameters (causing parameter misalignment/errors); guard against expansion by prefixing `,$arr` at the call site, indexing explicitly (`$c[1]`), or having functions write to `$script:` globals instead of receiving the array. Confidence: 0.8
- Calls on disposed GDI+ objects (Graphics/Bitmap after `.Dispose()`) surface as a generic "参数无效" (ArgumentException "Parameter is not valid") exception, not a disposed-object error — when that message appears in System.Drawing code, suspect double-dispose or a stale/not-reassigned canvas across iterations before suspecting the drawing arguments themselves. Confidence: 0.6
- Cross-mod dependencies inside this project family are consumed as locally published Maven artifacts (mavenLocal → `~/.m2`), not source/composite builds: FargoSoul publishes to mavenLocal (`com.fargo_soul:fargo_soul:1.21.1.1`, depends on `first:Lyra:1.21.1.8`), and sibling consumer mods (CreateSoul at D:\IDEA\CreateSoul) reference that artifact in their build.gradle. To make a consumer use the updated FargoSoul, the assistant must fix that consumer's dependency coordinates/version to the freshly published one (CreateSoul's stale `first:fargo_soul` group was simply wrong) and rebuild — and is expected to read/edit those out-of-workspace project files via shell since read_file is workspace-limited. Confidence: 0.7
